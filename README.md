# DOS2Linux


**DOS2Linux** — загрузчик на чистом ассемблере NASM, который реализует механизм `kexec` для DOS-совместимых систем.
Утилита позволяет пинком вышвырнуть 16-битный MS-DOS из памяти и сделать бесшовный прыжок напрямую в 64-битное ядро Linux без жесткой перезагрузки ПК (Hardware Reset). Проект полностью рабочий, Протестирован на реальном железе (Athlon 64, СRT-монитор и SATA-диск в режиме IDE Compatibility).

## Сборка

Код компилируется в плоский бинарный формат DOS `.COM`:

```bash
nasm -f bin kexec.asm -o kexec.com
```

## Использование

Параметры передаются прямо из командной строки DOS:

```cmd
kexec.com --kernel <FILE> [--initrd <FILE>] [--append "params"]
```

**Пример реального запуска:**
```cmd
kexec.com --kernel VMLINUZ --initrd INITRD.IMG --append "root=/dev/sda2"
```

## Как это устроено внутри

Код ломает ограничения процессора и передает власть ядру в 5 шагов:

1. Парсинг аргументов. (Просто обычный парсер который всё в понятный ASCIIZ конвертирует)

2. Включение Unreal Mode: Для работы памяти выше 1МиБ загрузчик строит таблицу gdt и загружает её, переводя процессор в Protected Mode, кэширует в скрытой части регистра FS плоский лимит памяти в 4 ГиБ с базой 0 и возврат в Real Mode, Лимит в 1 МиБ снят и DOS продолжает работать

3. Блочный конвеер чтения: Чтение файлов идёт блоками по 4КБ в локальный буфер через прерывание 21h. Код читает первые 512 байт ядра и парсит динамический размер реального режима ядра из поля setup_sects (Смещение 0x01F1) и копирует всю 16-битную часть ядра по адрессу 0x00090200.
vmlinuz и initrd: Protected-Mode часть ядра и образ рамдиска записываются в буфер и через разлоченный сегмент FS с помощью регистра в 32-бита назначения EDI, катапультируясь напрямую в верхнюю часть ядра (по 1МиБ до 6МиБ соответственно).

4. Заполнение LBP (Linux Boot Protocol): по фиксированным смещениям сегмента 0x9020 создаётся структура параметров:
  type_of_loader (0x0210) = 0xFF (Custom Loader)
  loadflags      (0x0211) = 0x21 (Ядро загружено высоко + используется куча)
  cmdline_ptr    (0x0228) = 0x00098200 (указатель на 0-терминальную строку cmdline)
  ramdisk_image  (0x218)  = 0x00600000 (адресс загрузки ramdisk'a)
  ramdisk_size   (0x21C) (Размер в байтайх)

5. Великий прыжок: через cli мы отключаем все прерывания. Сегменты DS и ES наводятся на 0x9020, а указатель стека сдвигается в область 9000h:0FFFEh для защиты данных от затирания и код прыгает в точку входа ядра - 9020h:0000h и получаем мы по итогу Decompressing Linux...
